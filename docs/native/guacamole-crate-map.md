# Guacamole crate map

What lives where in the Guacamole crates, feature by feature, with the openspec box that put it there. Moved out of [`CLAUDE.md`](../../CLAUDE.md) on 2026-11-13 (it had grown to 98 KB, and every agent session loads that file whole before doing any work). The project instructions keep one line a crate and point here; [`guacamole-design.md`](guacamole-design.md) still owns decisions and architecture.

A lane that changes what a crate does updates its entry HERE, not in the project instructions. The entries below are the text as it stood, one bullet a crate, long on purpose: grep for the file, the box id or the stand-in ledger key you're after.

## Story saves, as built

- **Story saves belong to profiles.** One save per profile per game, no slot picker. The profile that starts the game is the host and only its save advances; figure progress (XP, gold, upgrades) goes to the profile that placed the figure, so in co-op both kids' characters advance. Built (openspec AS.38, AU.3, AU.4, AU.15): the original's save scripts run on the VM and the host answers `system.save state` ([`story_save.rs`](../../crates/guacamole/src/story_save.rs), [`story.rs`](../../crates/guacamole/src/story.rs)), each save kept by the scripts' param names as JSON in `story_saves`, one row per profile per game per save layout (`FORMAT:fnv`, `1:50eea71a` on the 01.00 disc, pinned by tests; a row of another layout kept and ignored, one of the build's own that doesn't read never written over, a profile's delete taking its rows: [`saves.rs`](../../crates/guac-server/src/saves.rs)); the host is the profile unlocked on the phone that launched (`guac_server::saves::GameHost`, guacamole's driver alone, a refused launch or a profile switch moving nothing, cleared at the quit; a launch with none unlocked saves for the session alone); every level's start saves (the level initializer's save, three writes through a keeper on the server's runtime, off the frame), a level end saves nothing itself and the next start saves it, and a phone's quit makes the pause menu's save before the level comes down (bounded at 5 s); a later session resumes where the title's load goes: chapter 1 unless done, else level 214 unless done, else `level_hub_2_stage_<1 + done of 210, 202, 211>`, asked by name as AS.13 asks a level; the title's part runs in the level definition's place on a run's first walk (AS.130: `story_save::title`, `Vm::native_first`), so the hub's count, sky and next chapter are the save's, and a level end's just-done marks ride the carried words (stand-in ledger: `story-save`).
