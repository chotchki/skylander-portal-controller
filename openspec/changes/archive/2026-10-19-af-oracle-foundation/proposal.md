# Phase AF - Oracle foundation: an unattended, frame-locked RPCS3 and how far it drifts from itself

## Why

Every rung from AG on checks Guacamole against the original running in the patched RPCS3, and nobody knows yet whether that oracle can be a test at all. RPCS3 has NO deterministic mode (guest time comes from the host TSC, PPU and SPU run as OS-scheduled host threads), so two replays from one savestate start identical and drift, by an unmeasured amount. The oracle also can't be driven without someone at the Mac: an RSX capture or a savestate starts only from a keystroke on the focused game window or a menu click, and P6's input is digital, port 0 only and held by wall-clock sleeps, so it can't walk, fight or play co-op. AF builds the drivable oracle, measures its drift and turns the measurement into the tolerances AG and every later comparison use. Nothing reaches the TV.

## What Changes

- **The pin first, on chotchki's call** (design Open question 1). The in-tree `accfecd2d` dies at boot on the Mac (Metal's "attachmentIndex(220) must be < 8", upstream `7022a322a`, fixed upstream by `c938d3e049` + `d08d568d5e` the day after our pin); the `09d602fd5` copy AC.2 settled on boots Giants at 54.9 fps but is a binary, so no patch can go onto it. Whatever the pick, the oracle becomes a SOURCE build reproducible from this repo (pin + P1-P8 + the oracle series), with its binary hash, base commit and MoltenVK version recorded beside every observation. AF.1 gathers the evidence that needs no build (one async-shader boot of the existing in-tree build, the crash log) before the call.
- **A dev-only oracle series**, O1 up, in its own directory beside the product's P1-P8 ([`rpcs3-patches/README.md`](../../../../rpcs3-patches/README.md)), applied after them by its own script and never by the product's [`apply.sh`](../../../../rpcs3-patches/apply.sh) or its CI lane. Every verb extends P1's AF_UNIX listener and answers only when `GUAC_ORACLE=1` is in the emulator's environment, so a stray oracle binary is inert. The verbs, all keyed to the flip counter P1's heartbeat already carries:
  - capture and control: `RSXCAP` (the same flag Option+C sets), `SCREENSHOT` (a rendered frame for FLIP, which an RSX capture doesn't hold), `PAUSE_AT <flip>`, `RESUME` and `SAVESTATE`;
  - frame-locked input for ports 0 and 1: a schedule of digital buttons plus both analog sticks per pad, each entry taking effect at a named flip and held until the next, applied where the guest reads its pads so host timing can't smear it, with a readback of what the guest actually read and when.
- **Memory without a memory patch.** RPCS3's own PINE server (off by default) reads and writes guest memory in bulk; the harness turns it on in an isolated oracle home and reads only while `PAUSE_AT` holds the emulator still. The RNG peek and seed are harness verbs over PINE, because the RNG's address is Giants knowledge and belongs in our Rust, not in an emulator patch that has to survive rebases. The reflection registry already names the type: `igMersenneTwisterRandomNumber` (2,508 bytes, an MT19937 state). AF's census finds the live instances, what seeds them and which gameplay draws from them, and records whatever else the game draws randomness from.
- **A Rust harness, the repo's existing pattern**: a codec unit-tested line by line, a fake AF_UNIX server (P1 + the oracle verbs + PINE) as the executable spec, and `#[ignore]`d live tests that drive the real oracle on the Mac, as [`crates/rpcs3-control/tests/ipc_loopback.rs`](../../../../crates/rpcs3-control/tests/ipc_loopback.rs) and [`live_launch.rs`](../../../../crates/rpcs3-control/tests/live_launch.rs) do for P1. Two crates: `crates/guac-oracle`, pure (input scripts, traces, envelopes, the comparisons, an MT19937 model), which later rungs' tests can use without depending on anything RPCS3; and `tools/oracle-harness`, which drives the emulator and writes only outside any work tree.
- **The divergence measurement on the Mac**: one fresh gameplay savestate on the chosen pin, 10 replays per input script (idle, and a scripted walk) from `Start Paused`, each in a fresh process with a fresh copy of the figure, observed at the same flips: the RNG state, actor transforms, a screenshot, and an end-of-run savestate for a whole-memory diff count. A second set with mid-run checkpoints measures whether pausing to observe moves the run. The result is a usable horizon per observable (how many flips the 10 replays stay together) plus the spreads. The HTPC's runs stay with the Windows/HTPC bring-up ([`openspec/backlog.md`](../../../backlog.md)).
- **Tolerance metrics**, all four defined now: trajectory envelopes, event-sequence equality, totals, FLIP thresholds on frames. The trajectory and frame ones are calibrated from the measurement and accepted only if every replay passes against an envelope built from the other nine and a deliberately perturbed run fails; AF observes no game events or XP, so those two get their numbers from the first rung that does (AH).
- **The game-magic guard learns savestates.** AF makes them routinely: `RPCS3SAV` joins the magics (raw and gzip states) and a zstd file is checked again after inflating its head, the way a gzip one already is ([`crates/guac-extract/src/magic.rs`](../../../../crates/guac-extract/src/magic.rs)).
- **AC doesn't wait on AF.** `RSXCAP`, `SAVESTATE` and `SCREENSHOT`, with P1's `LOAD` and P6's menu presses, make AC.13's session unattended, and AF's capture check runs on AC.13's scenario so its output can serve AC.12, AC.13 and AC.18. AC.13 can still run attended on the `09d602fd5` copy first. Ticking AC's boxes stays AC's ([`ac-giants-decode-gate/tasks.md`](../../ac-giants-decode-gate/tasks.md)).

## Capabilities

### New Capabilities

None. `.openspec.yaml` sets `skip_specs: true`. AF is dev tooling plus a measurement of the emulator, not of the game: the oracle verbs' contract is the fake server in the harness's loopback test (this repo's executable-spec pattern for emulator patches), and the tolerances are method, owned by [`docs/native/guacamole-design.md`](../../../../docs/native/guacamole-design.md) (The oracle), which later rungs' specs cite. What the RNG census learns about the game goes into the design doc in our own words, and becomes a spec when AJ's VM draws random numbers.

### Modified Capabilities

None.

## Impact

- Track: Guacamole, rung AF, the oracle foundation. No kid-visible milestone. Stands on no rung; lands before AG (the first gameplay comparison) and gives AI its two-pad input.
- Disc serial: BLUS30968, read only by the oracle (its home's `games.yml` points at the dev's dump) and by AF.8's census over a savestate and the decrypted EBOOT, both outside the repo. guac-extract's output doesn't change (extract layout and IR stay at v1).
- Code:
  - `rpcs3-patches/oracle/` (the O-series, its apply and build scripts, its README section); the product's P1-P8, `apply.sh`, the patched-build CI lane and the pin are untouched;
  - [`.ci-local/build-mac.sh`](../../../../.ci-local/build-mac.sh) takes an optional source checkout (the default stays `vendor/rpcs3`, so the product's dev build doesn't change);
  - new crates `crates/guac-oracle` and `tools/oracle-harness`;
  - the guard's magics and its zstd re-check ([`crates/guac-extract/tests/no_game_bytes.rs`](../../../../crates/guac-extract/tests/no_game_bytes.rs)).
- Dependencies: a zstd decoder for the guard and the harness's savestate reads; a FLIP implementation (NVlabs' reference, AF.10 picks how it's called, and AC.18 can reuse it).
- New dev keys: `GUAC_ORACLE_EXE` (the oracle binary, outside the repo) and `GUAC_ORACLE_HOME` (its isolated HOME); outputs go to `GUAC_CAPTURE_DIR`, which gets its first reader. A savestate load deletes and rewrites RPCS3's hdd0 and hdd1, so the oracle never runs against the real `~/Library/Application Support/rpcs3`.
- Owning docs: [`docs/native/guacamole-design.md`](../../../../docs/native/guacamole-design.md) (The oracle, RE toolchain, Risks, Milestone ladder), [`rpcs3-patches/README.md`](../../../../rpcs3-patches/README.md) for the series layout, and [`CLAUDE.md`](../../../../CLAUDE.md) for the new dev keys, crates and the oracle series.
- Release reach: none. The oracle series never enters a product build, nothing in `guacamole` links the harness, and AF lands and archives on `2.0`. No `v*` tag carries anything from AF.
- Id: AF, the id the ladder, AC.13 and the research already cite, though [`openspec/config.yaml`](../../../config.yaml)'s rule reads AE (AE is unallocated, its M1 turntable not yet proposed); design Open question 2.
