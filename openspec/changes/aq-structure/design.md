# Design

## Context

- **guacamole is two compilation units, and the hot one is the binary.** 52,044 lines in 54 files (`5920f56`). The library ([`lib.rs`](../../../crates/guacamole/src/lib.rs)) is 16,909 lines in 21 files: the character renderer, the census, the level's scene, the props, the scripts bridge, the player loop, the GameController pads and the walkers. The binary is 35,135 lines in 33 files, its modules declared in [`main.rs`](../../../crates/guacamole/src/main.rs): the TV's screens, play, the level's load, the hero, the pads' layer, the hero's scripts, physics, the mirror and the shots, extraction and the intros. 12 of the 17 files over 1,000 lines are the binary's, and so is every file the day's merges conflicted in. A change in a binary module recompiles the whole binary (and under `cargo test` its unit-test build as well), never the library; a change in a library module recompiles the library and everything that links it: the binary, the `hero_view` and `video_spike` examples and the 10 integration-test files, each its own binary linking Bevy. Integration tests reach only the library, so a binary module is checked by its own unit tests and the e2e alone. AG.65's loop measured both sides: a log line changed in [`play.rs`](../../../crates/guacamole/src/play.rs) rebuilt `guacamole` in 3.45 s and `cargo test -p guacamole --no-run` in 5.55 s, an error's text in guac-script's [`vm.rs`](../../../crates/guac-script/src/vm.rs) the latter in 6.3 s. The package depends on `guac-server`, `guac-extract`, `guac-formats`, `guac-ir`, `guac-script`, `guac-motion`, `skylander-core` and `skylander-rpcs3-control` (for the `PortalDriver` trait), Bevy 0.20 and Avian.
- **Lanes are worktrees, two compiling at most.** Each worktree has its own `target/` (14-45 GiB each on 2026-10-21; a cold one is AG.65's 660 s of dependencies at opt-level 3); the Mac runs at most two compile lanes at `-j 4` since load 150+ hung it on 2026-10-19. A lane merges into `2.0` when it lands, and three of the six merges on 2026-10-21 conflicted in [`play.rs`](../../../crates/guacamole/src/play.rs), [`crates/guacamole/src/pad.rs`](../../../crates/guacamole/src/pad.rs), [`mirror.rs`](../../../crates/guacamole/src/mirror.rs), [`shots.rs`](../../../crates/guacamole/src/shots.rs) and [`hero_scripts.rs`](../../../crates/guacamole/src/hero_scripts.rs). The mirror is the shared file by construction: every subsystem's `/api/_test/tv` field (`focus`, `level`, `prepare`, `input`, `mode`, `hero`, `gait`) is built there.
- **The tick order is spread over five files.** `FixedUpdate` systems are added in [`hero.rs`](../../../crates/guacamole/src/hero.rs) (`HeroSystems::{Step, Gait, Camera}`, a step counter, the movers after the step), [`hero_scripts.rs`](../../../crates/guacamole/src/hero_scripts.rs) (`ScriptSystems::Step` before the hero's step, `Advance` between it and his gait), [`level.rs`](../../../crates/guacamole/src/level.rs) (the props stood before the step), [`scripts.rs`](../../../crates/guacamole/src/scripts.rs) and [`mirror.rs`](../../../crates/guacamole/src/mirror.rs) (the gait log after `HeroSystems::Gait`), each placing itself by its own before/after edge; the scripts' file is a library module, the other four the binary's. Inside the scripts' step the VM ticks placements in its own order. AH.59 found four places where that order puts something a step off the recordings, and puts the order in one place (decision 8).
- **Ids collide at merges.** A lane takes the next free box id in its worktree's copy of a change's task list, so two lanes take the same one and the second merge renumbers: nine renumber commits from 2026-10-20 22:35 to 2026-10-21 18:42.
- **What the tests repeat.** `cargo test --workspace`: 2,106 passed and 196 ignored in 147 binaries, 32.1 s (AG.65). The guacamole e2e, 73 tests in 277 s: every spawn is a `cargo run` into the repo's `target/` ([`crates/e2e-tests/src/lib.rs`](../../../crates/e2e-tests/src/lib.rs)'s `start_server`; AG.78 is its cold first build), a synthetic extract built in the spawn's own temp dir (`IntroFixture::build_in` and its walking and fighting variants: the synthetic dump, roster, model, level and script part) and AE.25's start pass, 144 keys (616-660 ms on a warm Metal cache and 2,406 ms with 32 of the keys new to it, in AG.43's runs of the real level); [`guacamole_intro.rs`](../../../crates/e2e-tests/tests/guacamole_intro.rs) also has ffmpeg encode `testsrc` and `sine` intros, three of them 30 s long, per test. The fixture builds its extract through guac-extract's own `ExtractRoot::checked` and `open`, which refuse a root inside any git work tree (`GUAC-E-EXTRACT-IN-CHECKOUT`), so it lives in a temp dir. guac-extract's eight disc tests that write (`giants_identity`, `giants_intros`, `giants_stages`, the model, level and fight stages', [`giants_transcode.rs`](../../../crates/guac-extract/tests/giants_transcode.rs) and `census_dumps`) each make a throwaway extract or report under `GUAC_EXTRACT_DIR`, and every one of them exercises what it writes. guacamole's and guac-script's disc tests write nothing: they read the dump in memory through the extractor's readers, and the VM's redo the same setup per test (`giants_chompy`'s 21 tests, `giants_eruptor`'s 10, `giants_init_chain`'s 7: the level's script part read and linked, the init chain run; decision 5 says which of it may be shared, AQ.4 prices it). guac-extract's own [`transcode.rs`](../../../crates/guac-extract/tests/transcode.rs) tests run a fake ffmpeg and encode nothing.
- **Stand-ins live in five kinds of place.** AG's design decision 2 table (15 rows) and AH's (20, plus Slides struck at AH.19), both bound for the design doc at AG.33 and AH.32; open boxes (AH.62's kept health); backlog lines (the swap's script reinstall, Titan feats, particles, combat sound, the HUD); and the code, where 61 lines in 27 files say "stand-in". No list says which box retires each, or what breaks if one is still in when its neighbour lands.

## Goals / Non-Goals

**Goals:**
- Boundaries chosen from measurements, and approved by chotchki before anything moves.
- Splits that land without a lane rebasing a moved file, and change nothing a test can see.
- Lanes that never take the same box id.
- Test runs that build each input once per content and still exercise everything they exercise today.
- Every stand-in with the box that retires it, and the dangerous ones retired before what they'd break.

**Non-Goals:**
- Behaviour, requirements or specs (`skip_specs: true`).
- Item 4, tests that couldn't fail: "not sure we can do anything on this." The reviews' mutants stay the check; the test survey records any it meets.
- Item 6's fix itself: it's AH.59's (decision 8).
- A Bevy, Avian or toolchain upgrade, a new linker, sccache or a shared target dir across lanes. The code survey measured the target dirs and proposed persistent lane worktrees instead (decision 9); AQ.30's rustix line puts guacamole's build on features its tests already use, no version moves.
- The product's behaviour or release (the product is frozen; AQ.5 turned down the one `guac-server` split, so the boxes that reach guac-server's or the product's manifests and tests change nothing they ship).

## Decisions

**1. The survey proposes the boundaries and chotchki approves them before any file moves.**
The bar is chotchki's "worthy of considering a split": the 1,000-line mark puts a file on the survey's list, it doesn't split it. A file is proposed for a split when the survey shows a cost: lanes conflicting in it, boxes from several concerns editing it, a rebuild it forces that a boundary would avoid, or concerns mixed in it that a reader has to page past. A 1,000-line parser with its property tests at the foot, or a test file of one subject, can stay. The survey ends in a proposal (crate boundaries, module splits inside them, the order) and chotchki approves, redraws or turns it down (AQ.5) before any file moves. The split boxes below are what the survey is expected to propose; it may redraw them.
Settled at AQ.5 (2026-10-23, chotchki: "I'm good with AQ.5's recommendations"), every recommendation taken as written: no file over the mark splits for its size alone (guac-script's [`vm.rs`](../../../crates/guac-script/src/vm.rs) and guac-server's [`http.rs`](../../../crates/guac-server/src/http.rs) and [`crates/guac-server/src/state.rs`](../../../crates/guac-server/src/state.rs) never conflicted, and a split buys no rebuild, decision 2; AQ.6 and AQ.12 struck), and the moves approved are the ones a merge or a cycle asks for, in decision 3's order.

**2. A seam becomes a crate only where a measured trial split pays; otherwise it's a module split.**
- A crate buys parallel compilation, a rebuild that stops at the crate's dependents (a change in the TV's screens recompiling their crate and what depends on it, rather than all 35,135 lines of the binary), integration tests that can reach what's in it (nothing in the binary is reachable from one today) and a boundary a lane can't reach through. It costs `pub(crate)` items turning `pub` across the boundary, `test-hooks` and `dev-tools` threaded through each new crate, test helpers shared across crates (a feature or a support crate), the orphan rule, and maybe little time back: Bevy's systems are generic, so much of the codegen may still land in the crate that builds the `App`, and AG.65's loop already rebuilds the binary in 3.45 s after a one-line change.
- What no split of our crates buys: the cold build. AG.65's 660 s is the dependencies at opt-level 3, paid once per target dir, and a split of the workspace's own code leaves it as it is. Fewer cold target dirs would (a warm dir kept per lane, a dependency cache shared across worktrees), and AQ.3 (e) measures that share before anything is proposed. Measured: a fresh worktree is 1,390.5 s of cold builds and 7.3-11.3 GiB of dependencies, so a warm dir per lane is decision 9's (AQ.32); a shared `CARGO_TARGET_DIR` stays out, since cargo locks the dir for a build (two lanes would serialize) and the e2e harness pins `repo.join("target")`.
- So the code survey measures before it proposes: `cargo build --timings` per crate, the rebuild after a one-line change in each hot file, and one trial split of one seam on a throwaway branch, measured the same way. A seam whose trial doesn't pay, or whose boundary too many items cross, becomes a module split.
- A crate boundary can't cut a cycle. The survey's module graph (the `use crate::` edges and the system-set ordering edges) names each cycle; a seam inside one stays a module, or the cycle is broken first in a box of its own.
- The mirror is the main cycle risk: it reads every subsystem. Each subsystem builds its own `/api/_test/tv` report beside its code and the mirror composes them, so the mirror can sit on top and a lane adding a field edits its subsystem, not the shared file.
- **The trial didn't pay, so no crate now** (AQ.3; AQ.5). [`crates/guacamole/src/hero.rs`](../../../crates/guacamole/src/hero.rs) and [`crates/guacamole/src/physics.rs`](../../../crates/guacamole/src/physics.rs) as `crates/guac-hero` on a throwaway branch: edits staying in the binary 0-0.5 s faster to build, edits in the moved files 0.1-0.5 s faster to build but 2.2 s SLOWER under `cargo test` (5.29 → 7.54 s), because cargo's dependencies are per package, not per target, so the crate the binary needs became a dependency of guacamole's library and its 12 integration tests too; and `cargo test -p guac-hero` resolved a fourth Bevy. A file split inside a crate buys no rebuild either (r = 0.16 between a binary file's size and its rebuild). So the binary's six cuts are module moves (AQ.7-AQ.10), and crates come back only after them (AQ.11), with the binary in a package of its own, the one shape that could pay (unmeasured).

**3. One split at a time, moves only, with nothing in flight on its files.**
- A split starts when no lane is editing the files it moves, and the session launches none on them until it merges; lanes launched after it start from it. Two splits in flight, or one beside a lane in its files, means rename-against-modify merges, the conflict this change exists to cut.
- A split's commit is moves plus the `mod`, `use`, visibility and crate-manifest lines a move needs, so `git diff --color-moved` and `git log --follow` read it as moves. A fix found while moving is its own commit after.
- Verified by: `.githooks/pre-push` green; `cargo test --workspace`'s passed and ignored counts the same before and after (tests move, none appear or vanish); the guacamole e2e at its count; the disc tests whose code moved rerun with their numbers unchanged; and the rebuild after a one-line change in each moved file against the survey's, which says whether the split paid.
- The cuts in the level's and play's neighbourhood (AQ.9, AQ.10) stand on AH.59 (decision 8). Before it their order was edges between those very files, so a system moved then could land in another place in the step with nothing failing until a fight ran a step late, item 6's own failure. AH.59 has landed: the order is one list in [`frame.rs`](../../../crates/guacamole/src/frame.rs), and a moved system keeps its place.
- Moves wait on each other where they touch the same files, in the survey's order: the shared test helpers first (AQ.33), then the mirror (AQ.8), [`tv.rs`](../../../crates/guacamole/src/tv.rs)'s shared state (AQ.7), the level's cuts (AQ.9) and play's (AQ.10).

**4. Per-lane id blocks** (item 3; [`openspec/config.yaml`](../../config.yaml), AQ.1).
- The session hands every lane it launches a block of new task ids per change the lane may add boxes to, written into its prompt (with AH.65 the highest on `2.0`: AH.66-AH.75 to one, AH.76-AH.85 to the next), starting past the highest id `2.0` or any block still out holds. A lane launched alone gets one too: another may launch beside it before it merges, and a lane taking the next free id would collide with that one's block. A lane numbers new boxes from its block only, in order; it never renumbers a box `2.0` or another lane holds; a box past its block, or in a change it holds no block in, goes unnumbered in its report for the session to number at the merge. The session's own boxes (a merge's findings) take ids past every block out, and with no lane out it takes the next free id. A new change id goes out the same way: at launch to a lane that may propose one, otherwise left unnamed in its report. Unused ids stay gaps, as change ids do.
- Rejected: (a) renumbering at the merge, today's way (Context): each one rewrites cross-references, while a commit subject or code comment that cited the old id keeps citing it; (b) a lane suffix (`AH.19a`), which breaks `<ID>.<N>` and reads as a split of AH.19; (c) one shared counter file, which lanes in separate worktrees can't see until they merge.

**5. Caches hold a test's inputs only, keyed by content.**
- What may be cached: an input a test needs and doesn't test (the synthetic intros a TV test plays, the synthetic extract a phone test starts from, the binary the harness spawns, the dump's script part a VM disc test reads and links before the step it checks). What may never be: the output of the code a test exists to exercise, so guac-extract's transcode, stage and census tests keep transcoding and extracting on every run, and `giants_init_chain` keeps running the init chain; a cache serving their output would turn each into a check of the cache.
- The key is a hash over everything that decides the output: the source of the builder and of every crate it writes through, hashed whole (the synthetic extract is laid out by guac-extract's `open`, guac-ir's types and guac-formats' `SfoBuilder`, so `crates/e2e-tests/src`, those three crates' sources and [`Cargo.lock`](../../../Cargo.lock); any edit misses, over-invalidation being the safe direction), the tool's identity (ffmpeg's `-version` lines, the arguments, the lavfi source string) and the versions the output records (`IR_VERSION`, `LAYOUT_VERSION`, the transcode `TARGET`). Never a modification time or a file's presence.
- An entry is built in a temp sibling and renamed into place, so a killed run or two tests racing never leave half of one. A spawn never runs on the entry itself: it gets its own APFS clone (`clonefile`, `cp -c`; a plain copy off APFS), so nothing a spawn or the server writes reaches the entry or another spawn, and no test has to know whether guacamole writes into its extract.
- Synthetic entries live outside every git work tree: the fixture and guacamole both open the extract through the in-checkout refusal (Context), so a cache under `target/` would be refused on its first build. They go under the user's cache folder (`~/Library/Caches/guac-test-cache/<kind>/<key>/` on the Mac), which every worktree shares safely since the key is the content; each kind's older keys are pruned when a new one lands and deleting the folder is always safe. Nothing from a disc is ever written there: a disc read a test shares stays in memory, once per test binary (a process-wide fixture each test clones), and guac-extract's disc tests keep their throwaway extracts under `GUAC_EXTRACT_DIR` (the hard rule).
- Each cached fixture keeps one test that builds it fresh and checks it, so the builder can't rot behind its cache, and `GUAC_TEST_CACHE=off` builds everything fresh for a run that wants it (the phase exits).
- The start pass is the exception to weigh, not a cache to add: macOS already keeps compiled pipelines per user (AE.25), which is why the warm pass in Context is already cheap. Skipping it under a test-only switch would put a path in the binary that only tests take. The test survey prices it beside fewer spawns (several checks on one server where they can't interfere); the default is to keep it. AQ.4 priced it (816-887 ms a spawn, about 1 s on the critical path of the 6 tests that read the TV before a phone) and AQ.5 kept it.
- **Settled at AQ.5: nothing cached across runs.** The biggest cost in the tests was the drive flush, not a repeated build (AQ.4: [`crates/guac-extract/tests/stages.rs`](../../../crates/guac-extract/tests/stages.rs)' 3,977 `F_FULLFSYNC`s were 92-94% of its time), so `TMPDIR` on an APFS RAM disk takes it (decision 9), and with it most of what AQ.14's synthetic-extract cache would have saved (21-26 s a run on the SSD, ~1.5 s beside the disk); AQ.13's cross-run intro cache would add ~0.7 s over a once-per-binary fixture. chotchki turned both down, so a shared input is built in the test process from the current source: once per test binary (the intros, AQ.13; the VM disc tests' read and link, in memory, AQ.16) or once per run (the binary the e2e spawns, AQ.15). The rules above (the key, the temp sibling, the clone, the folder outside every checkout) stand for any cross-run cache a later box adds.

**6. Overtesting is two tests on one path to one assertion.**
Typical shapes: a headless test and an e2e checking the same TV behaviour; e2e tests that each spawn a server to reach the same state; disc tests re-deriving the same reads. A test is deleted or narrowed only when every mutant it fails on fails another test too: the survey writes the mutants, the box runs them and lists them. `cargo test --workspace`'s count then changes only by the removals named in that box. AQ.4 found five pairs and ran 13 mutants on them (35 outcomes, the same at its review); AQ.17 removes five tests, two of them after a narrower test takes their one unique catch.

**7. The stand-in ledger.**
- One table, in the design doc where AG.33 and AH.32 move AG's and AH's stand-in tables (whichever of the three lands first writes it, the others add to it), extending their columns with two: the box that retires it (a box id, or the backlog line until its rung is proposed; a rung's name alone isn't enough) and its hazard (what goes wrong if it's still in when a named box lands, and how it would show; or none, with why).
- Its rows: every row of both tables, every stand-in an open box or a backlog line names, and every code comment that calls something one. Each comment points at its row, so the ledger and the code can be checked against each other with a grep.
- Ordered by hazard: a hazardous row's retiring box goes ahead of the box it endangers, in that box's "on" list. Known so far: (1) the swap's script reinstall (`hero_scripts::reinstall`), which resets Setup_001 and the Chompies on every swap once AH.25 runs the fight on the TV; no box retires it today, so the ledger adds one to AH (the deactivate path: his file's placements and clones off the VM, the next hero joined into the same run) ahead of AH.25; (2) AH.62's kept health, which the reinstall would also reset, with it; (3) the walker a hero falls back to when his scripts aren't in the level's part or his join failed: he walks and can't attack, so a run that fell back passes every walking check, and the ledger names which runs assert his scripts are driving; (4) the host answering every point as on screen (AH.20), harmless while an orb's idle bounce is its only reader, hazardous once a reader gates play on it.

**8. Item 6 is AH.59, ahead of AH.25.**
AH.19's review called the hurt chain a step earlier and the pushes matched AH.10's frame for frame: the root cause is the order, not the pushes. AH.59 measures the original's per-frame order on the oracle once (which of the scheduler's three groups each placement and engine phase ticks in, and in what order, through a frame of the fight, beside the decompile and the June state's live lists) and encodes it as one explicit Bevy schedule of named sets, declared in one module, that every `FixedUpdate` system joins; the library's [`crates/guacamole/src/scripts.rs`](../../../crates/guacamole/src/scripts.rs) adds one too, so the module has to be one both the library and the binary can name (the library, or a crate under it). AH.25 stands on it, so the first fight on the TV isn't tuned around a step-late order, and AQ's gameplay splits stand on it (decision 3). The box lives in [`ah-first-fight/tasks.md`](../ah-first-fight/tasks.md); AQ only orders against it.

**9. Build and test plumbing pays where a split doesn't** (AQ.3, AQ.4; settled at AQ.5).
- One Bevy for guacamole's build and tests (AQ.30): the tests' `tempfile` turns on rustix's `default`, which costs a second Bevy and Avian per cold target dir (272.8 s, 1.17 GiB); `rustix = "1"` among guacamole's dependencies ends it (probed: 0 dependency units rebuilt). The line breaks silently when a dev-dependency turns on another shared feature, so a guard in `.githooks/pre-push` fails on the drift; cargo-hakari only if the guard can't catch it.
- [`giants_roster.rs`](../../../crates/guac-extract/tests/giants_roster.rs) into guac-server's tests (AQ.31): the one file that makes guac-extract dev-depend on guac-server, so 20 relinks off every guac-server edit.
- Persistent lane worktrees (AQ.32): two fixed worktrees outside `/private/tmp`, each lane switched into a free one, so no lane pays the 1,390.5 s cold set.
- `doctest = false` on the 16 libraries with no doctest (AQ.36): 4.4 s a run, 13.3 s after a rebuild.
- `TMPDIR` on a 2 GiB APFS RAM disk for test runs (AQ.35): `cargo test --workspace` 36.6-45.4 → 18.4-18.5 s, every flush still called. APFS only, since an HFS+ disk's whole-second times fail guac-extract's [`crates/guac-extract/tests/identity.rs`](../../../crates/guac-extract/tests/identity.rs) every run, and only once oracle-harness's lock test stops racing on it (AQ.34: 3 of 64 runs there, 0 of 100 on the SSD). Mac only.
- Not taken: `BUILD_TOKEN` stamped in each binary rather than guac-server (about 1 s a git operation, since a build script is per package, for a product release); the workspace's third Bevy (the product's features unifying into Bevy's dependencies, 882 CPU-s cold), which ends at G1 by itself, where declaring the same features on guacamole's side would be another list that breaks silently.

## Risks / Trade-offs

- [A crate split doesn't pay: the codegen stays where the `App` is built] → it didn't (AQ.3's trial, decision 2), so no crate now; AQ.11 measures again after the cuts, with the binary in a package of its own.
- [Visibility widens: items go `pub` to cross a boundary] → the trial counted 39 for one leaf; none crosses until AQ.11, and a seam with many stays a module.
- [A move hides a change] → moves only, one commit per split, `--color-moved` (decision 3).
- [Lanes stall while a split runs] → the splits run one at a time between lanes, in the order chotchki approves; a lane wanting a file mid-split waits for its merge.
- [The test count drifts unnoticed] → the counts before and after each split and each narrowing are recorded in its box.
- [A shared input is stale] → nothing is kept across runs (decision 5): each fixture is built in its test process from the current source, the e2e never spawns a binary older than its source (AQ.15), one test builds each fixture fresh and `GUAC_TEST_CACHE=off` builds them per test at the phase exit.
- [A spawn's writes leak into a fixture or another spawn] → every spawn's extract gets its own clone of the fixture's files, never the fixture (decision 5).
- [The one-Bevy line drifts] → AQ.30's guard in `.githooks/pre-push` fails when guacamole's build and test graphs part, naming the crate.
- [The RAM disk changes what passes] → APFS only (HFS+ fails guac-extract's identity test every run), oracle-harness's lock race fixed first (AQ.34), every command it wraps still working without it (AQ.35).
- [A persistent worktree's target dir fills the disk] → the session records the dir's size and the Mac's free disk at each launch, and cleans a dir past the size AQ.32 sets between lanes, never during one.
- [A lane fills its id block] → it lists further boxes unnumbered and the session numbers them at the merge (decision 4).
- [The ledger rots] → every code comment that says "stand-in" points at a row; the docs box checks it with a grep.
- [Features unify across new crates] → the product's release build turns off `guac-server`'s defaults so its features don't unify with guacamole's; a crate AQ.11 adds declares its features explicitly and its own test graph goes through AQ.30's guard (the trial's fourth Bevy).

## Migration Plan

Nothing persisted changes shape (decision 5 covers the test inputs), and the RAM disk lives for the one command it wraps. Each move is a revert away. AQ.5 turned down AQ.12's `guac-server` split, the one change that would have reached the product, so AQ archives on `2.0` once AQ.0 holds, with no release.
