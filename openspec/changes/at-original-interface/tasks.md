# Tasks

## AT. The original's interface: its scripts on the VM, its sprites and text drawn through Bevy's UI

No change-wide gate: each box names what it stands on, other changes' work by id or by name, and runs when that has landed. Each box names its gate (design decision 4): **scoped** for a pure-crate box (`cargo fmt --all --check`; `cargo clippy -p <crates> --all-targets -- -D warnings` and `cargo test -p <crates>` through [`.githooks/ram-tmpdir.sh`](../../../.githooks/ram-tmpdir.sh) for the crates it touches; its `#[ignore]`d disc tests by hand; `cargo check -p guacamole` only when it changes something guacamole already uses), so a component lane skips the multi-hour runs; **full** for a wiring box ([`.githooks/pre-push`](../../../.githooks/pre-push), clippy of guacamole with `--features test-hooks` and with `--no-default-features`, and the guacamole e2e). Every merge into `2.0` runs the full gate either way. A box reading guest memory or booting the oracle is the RPCS3 lane's, one at a time. The research behind every number below is in `~/workspace/guacamole-research/at-interface/` (2026-10-31).
